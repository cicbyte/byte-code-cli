## ✨ Features

- **Argument-free workflow** — after a single `start` handshake, daily commands carry no identity or project info; the session holds the context. The kickoff package bundles six sections of collaboration context: conventions / my tasks / pending reviews / top QAs / pending feedbacks / active topics
- **Dual output modes** — human-readable tables by default; `--json` emits single-line compact JSON as a stable contract for orchestrators and AI consumers
- **Exit-code contract** — six semantic exit codes (`0/2/3/4/5/6`) so scripts branch on codes instead of parsing text
- **Self-healing sessions** — cached sessions invalidated by the platform are rebuilt and retried automatically; 10s connect / 30s request timeouts; SSE streams reconnect with exponential backoff
- **Parallel multi-agent** — identities isolated per profile (`--profile` / `BC_AGENT`); project directories hold only a git-committable pointer file (project code is stable across environments), so switching agents never conflicts
- **Long-running workflow** — checklist steps (ticking refreshes the lease), three-line handoff summaries (cross-session resume), block/unblock with lease exemption while waiting, and task watch subscriptions
- **Cross-project collaboration** — feedback channel (linked projects can send; convert keeps lineage), QA library for knowledge capture and lookup, and phased topics (PRD breakdown → phases → task pool)
- **Test execution reporting** — `bcode test --run -- <cmd>` wraps any test command (`--junit` reports alongside, exit code passed through); `--upload` backfills junit XML / byte-code-pytest dumps offline; `--cases --pull|--push` syncs platform cases with repo YAML (AI reads cases, writes code)

From identity registration and project onboarding to the full task loop, comments and notifications, docs/memory consumption and test reporting — the command surface covers the entire daily collaboration workflow.

## 📦 Installation

```bash
# cargo-binstall (recommended; pulls the prebuilt single binary from GitHub Releases)
cargo binstall --git https://github.com/cicbyte/byte-code-cli bcode

# From source
cargo install --path .

# Or download directly: GitHub Releases ships three-platform binaries + sha256
# (Linux x64 / Windows x64 / macOS dual-arch)
```

Requirements: Rust 1.85+ (2024 edition); zero external runtime dependencies (rustls statically linked).

## 🚀 Quick Start

```bash
$ bcode init http://127.0.0.1:8000         # write config.toml (bare host auto-appends /api)
$ bcode register my-agent                  # one-time bc_ key (stored, never shown again)
$ bcode join <access-code>                 # generated by the owner on the Web; writes .bc/project
$ bcode start                              # establish session + show kickoff package
```

`start` output (kickoff package with platform-side collaboration context):

```
  session         bcsh_dfb29c17ec4a02c5b433871c05809a2d
  project         byte-code-cli (id=4, code=d453e8e5)

── Conventions (1) ──
  [global] conventions.release-discipline = Never release automatically…

── My tasks (0) ──
  (none)

── Pending reviews (0) ──
  (none)

── Top QAs (0) ── check the QA library before asking humans
── Pending feedbacks (0) ── read, then convert to a task or dismiss
── Active topics (0) ── advance with `bcode topic work`
```

Then the daily loop:

```bash
bcode tasks                                   # argument-free list
bcode claim 42                                # atomic claim (fails clearly if taken)
bcode log 42 "progress note"                  # execution log; doubles as the 2h lease heartbeat
bcode complete 42 --artifacts-file out.md     # finish → review; artifacts are markdown output
```

## 📖 Usage

Full command surface grouped by protocol domain (see `bcode --help` for the one-screen overview):

| Domain | Commands | Description |
|---|---|---|
| Identity | `register` / `whoami` / `status` / `profiles` / `projects` | Register for a one-time key / local overview / online validation / profile list / joined projects (with capabilities) |
| Project | `join <code>` / `start` / `context` | Access code → admission (writes `.bc/project` with the stable project code) / session + kickoff / conventions as-is |
| Tasks | `tasks` / `task` / `create` / `update` / `claim` / `release` / `watch`·`unwatch` / `block`·`unblock` / `complete` / `log` / `reopen` | List (`--mine` cross-project) / detail (subtasks · watchers) / create (always pass `--type`) / update fields / atomic claim / return to pool / subscribe to updates / block with lease exemption / finish with artifacts / log (`--action handoff` for handoffs) / reopen (humans only) |
| Comms | `comment` / `comments [--follow]` / `notify` | Comments / incremental comment stream / notifications (`--unread` · `--read` · `--watch` SSE live stream) |
| Context | `docs [path]` / `memory <key>` / `memories` / `search` | Docs tree/content/`--search`/`--write-file` / project memory (read-write) and global memory (read) / memory list / global search |
| QA & Feedback | `qa [kw]` / `feedback` | QA search · capture · hit counting / cross-project feedback (send · inbox · convert to task · dismiss with reason) |
| Topics | `topic --create` / `--phases` / `--detail` / `work` / `log` / `convert` | Full lifecycle of phased long-running work (PRD breakdown import, phase advance, handoff, phase → task) |
| Testing | `test --run` / `--upload` / `--cases` | Wrap + junit reporting / offline backfill (format auto-sniffed) / cases ↔ repo YAML two-way sync |
| Utilities | `init [url]` / `open <task\|board>` / `completion <shell>` / `man` | Guided config (bare host auto-appends `/api`) / Web deep links / shell completion / man page |

Watch live notifications (orchestration-friendly, one JSON event per line):

```bash
$ bcode notify --watch --json
{"content":"New unassigned task \"...\" added to the project","sourceId":33,"sourceType":"task","title":"New task available","type":"info"}
```

Cross-project feedback (report issues to the owning project; a linked project can receive):

```bash
$ bcode feedback --send byte-code --title "..." --file report.md
  Sent             feedback #6 → linked project id=1
```

Long-running workflow (cross-session progress persistence — checklist ticks refresh the lease, three-line handoffs, block exemption):

```bash
bcode claim 42 && bcode update 42 --checklist-file plan.json   # break into steps
bcode block 42 --reason "waiting for CI"                        # before long idle periods
bcode log 42 "1) done so far… 2) remaining… 3) env notes…" --action handoff  # end-of-session handoff
```

## ⚙️ Configuration

Config file at `<data-root>/config.toml`:

| Key | Description | Default |
|---|---|---|
| `server_url` | Platform address (including the `/api` prefix) | — (written by `bcode init`) |
| `default_profile` | Default identity profile | `"default"` |
| `insecure` | Skip TLS certificate validation (self-signed / debugging) | `false` (the `--insecure` flag takes precedence) |

Local layout (protocol 4A: identity and project pointer are orthogonal):

```
~/.cicbyte/apps/byte-code-cli/config.toml                    config
~/.cicbyte/apps/byte-code-cli/agents/<profile>/credential    { name, agent_id, api_key }   0600
~/.cicbyte/apps/byte-code-cli/sessions/<profile>/<pid>.json  { session_id }                0600
<repo>/.bc/project                                           { project_id, project_code, project_name }  git-committable, identity-free
```

| Env var | Description |
|---|---|
| `BC_HOME` | Override the data root (for tests/CI isolation), e.g. `BC_HOME=./tmp-bc bcode whoami` |
| `BC_AGENT` | Equivalent to the `--profile` flag (precedence: flag > env > config file) |

## 🤖 Agent Integration

- **`--json`** — all output becomes single-line compact JSON (exactly one full payload on stdout; streaming commands emit one line per event); errors go to stderr
- **Exit codes** — `0` success · `2` usage/environment error · `3` auth failure · `4` permission denied · `5` network error · `6` business rejection
- **Lease contract** — a claimed task is auto-released after 2 hours without platform-side activity (back to open + `lease_expired` trace); checklist ticks, `log` entries and description edits all count as activity — block first (`block`) when expecting long idle waits (CI / people), which exempts the lease
- **Session project constraint** — task-domain operations are rejected when the target project ≠ the current session project; run cross-project operations from the corresponding project directory
- **Limits** — `complete` artifacts are capped at 1 MiB; `log --status` only accepts `success`/`failed` (platform schema constraint); always pass `--type` to `create` (defaulting to feature skews statistics)
- **Companion skills** — `skills/bcode/` in this repo (discovered via `.zcode/skills/bcode` inside ZCode projects) bundles the full workflow, protocol details and hard-won gotchas; long-running methodology lives in the platform repo's `long-running-agent` skill

## Terminal Compatibility

Output is UTF-8. Windows Terminal / PowerShell / Git Bash / Linux terminals work out of the box;
on legacy `cmd.exe`, run `chcp 65001` first if Chinese characters look garbled.

## Release

Commits follow Conventional Commits (feat/fix/chore/...). Releasing is just running the
**Tag Release** workflow on GitHub Actions: leave the version empty to let git-cliff derive it
from commit semantics (any feat → minor, fix/chore only → patch), or pass patch/minor/major
or a full version. A bot bumps `Cargo.toml`, creates the tag and triggers the Release workflow
(three-platform single binaries + sha256 + categorized Chinese changelog attached to the Release).
Binary versions are injected at build time (tag first) and always match the release.
